# RouMy新方針における roumy-data の役割

本リポジトリの全体戦略ドキュメントは `murata1028/RouMy` の `docs/STRATEGY.md`（ブランチ `claude/roumy-strategy-redesign-1e9fb0`）を参照してください。

## このリポジトリの新しい位置づけ

**RouMyプロジェクト全体の唯一の正データソース（Single Source of Truth）。**

現状、GTFS由来のデータ（`stops.json` / `routes.json` / `trips.json` / `calendar.json`、広電=KODEN・広交=HIROKOU双方）はこのリポジトリにまとまっているが、`RouMy` 本体・`kinoko-art/Bus-scan` など各アプリ側がそれぞれ独自にデータを取り込む構造になっている。新方針では以下を推奨する。

1. **全クライアント（RouMy本体、旅程プランナー、OCR判定機能）はここのデータを唯一の参照元とする。** 各アプリ側での独自データ保持・二重管理を廃止する。
2. **PASPY廃止→ICOCA等IC移行のような制度変更を、路線・停留所単位のメタデータとして継続的に反映する。** これは大手経路検索アプリが手薄になりがちな「地域の今の困りごと」への対応力の源泉になる。
3. **停留所名の表記ゆれ（電停／バス停／駅の別名）の正規化テーブルを、このリポジトリ内に一元管理する。** 各アプリで別々に正規化ロジックを持たない。
4. 将来のPhase1（経路探索エンジン開発）に向けて、**乗換に必要な徒歩接続時間（stop間の乗換テーブル）** をこのリポジトリのデータとして追加整備する。

詳細な背景・全体戦略は本体リポジトリの STRATEGY.md を参照。
